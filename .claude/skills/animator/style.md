# Правила стиля (нарушать нельзя)

## Драматургия ролика (~60–70 сек, ~125 слов)
Это меню-опора, а не жёсткое предписание порядка ролей (см. `scriptwriter.md` — приём
диктует структуру). Типичная форма:
1. **Хук** (0–5 с): интрига или обещание. Без «привет, сегодня мы поговорим о».
2. **Объяснение**: 2–3 сцены, одна мысль на сцену.
3. **Углубление**: один «вау-факт» или «проверь сам» — то, чего нет в первой
   строке Википедии.
4. **Финал**: выжимка + мостик к следующему ролику.

Всего **5–6 сцен** (не 7): столько же, сколько идей в gap-скане режиссёра.

## Текст реплик
- Весь эпизод: **110–140 произносимых слов, цель ~125** (голос Fenrir читает
  размеренно: 140 слов ≈ 70 сек — это потолок). Источник правды по словам и
  длительности — `.claude/agents/scriptwriter.md`; здесь и в `ROADMAP.md` числа
  могут отставать — при расхождении верь scriptwriter.md.
- Устная форма: числа словами, без markdown, короткие предложения. Разговорно,
  на «ты», без канцелярита и без клише («в современном мире», «давайте разберёмся»).
- Каждый термин — через разметку `{форма-показа|форма-озвучки}` по словарю
  транслитерации (`~/.claude/commands/tts.md`): `{TCP|ти си пи}`,
  `{SSH|эс эс эйч}`, `{DNS|ди эн эс}`. Обе части — реальный текст, никогда
  буквально «SHOW»/«скажи» (это имена мест для подстановки, не значения).
  Ударения в спорных словах — U+0301: «ша́га».
- Точность фактов важнее краткости: не упрощай до неправды. «Углубление» должно быть
  технически корректным и проверяемым.

## Композиция кадра (1080×1920)
- **Полоса кадра (единственный источник чисел):**
  - `y 0…150` — статус-бар/аватар платформы, ничего смыслового.
  - `y 150…1330` — рабочая зона: сюда весь смысл.
  - `y 1330…1390` — воздух под караоке.
  - `y 1390` — караоке-субтитр (движок, `theme.ts karaokeY`).
  - `y 1500+` — UI платформы (плашка описания/хэштегов, бейдж «ИИ», строка
    видимости, «Поделиться»). Проверено по живому YouTube Shorts 19.08.2026:
    перекрывает низ сильнее, чем кажется на глаз.
  - Нижний бейдж/плашку визуала ставь на **y≈1200** — одно число, не подбирай
    на глаз. (`theme.ts safeBottom: 1500` — это граница UI, не потолок смысла.)
- ≤4 **смысловых элемента** в кадре одновременно. Смысловой элемент — объект,
  который зритель отслеживает: панель, устройство, узел, поток, диаграмма.
  Ярлык-подпись объекта в счёт НЕ идёт; самостоятельная текстовая плашка
  (бейдж, врезка) — идёт. Это определение единственное: `animation-director.md`
  и `catalog.md` на него ссылаются, не переопределяют. Сомневаешься — дели на
  две сцены.
- Подписи узлов ≤20 символов, лейблы пакетов ≤14, строки кода/терминала ≤46.
- Цвета только семантически: accent — главное, accent2 — вторая сторона,
  success — успех/итог, danger — атака/ошибка, warning — предупреждение.

## Что движок делает сам (сценарию и раскадровке думать не нужно)
- **Переходы между сценами**: slide-up (в outro — fade) + вуш. Автоматически.
- **Звук**: вуш/поп/клик/дзынь/слэм на событиях, фоновая подложка с приглушением
  под голос. Автоматически.
- **Дуги пакетов**: пакеты в diagram летят по чередующимся дугам. Автоматически.
- **Подсветка кода**: сцена code принимает `language` (bash/python/json/yaml/c/
  typescript, по умолчанию bash) — укажи правильный.
- **Lottie**: примитив `LottieGlyph` рендерит анимацию из `video/public/lottie/
  <name>.json` — если для нового визуала нашлась готовая бесплатная
  Lottie-анимация, положи файл туда и используй (лицензию проверь: бесплатные
  LottieFiles — можно без атрибуции).

## Моушн: что даёт движок и что обязан придумать режиссёр

**Движок даёт сам — заново не проектируй:**
- Фон дрейфует (сетка, частицы, дышащее пятно света).
- Сцена входит пружиной; лёгкий Ken Burns ~5% на всю сцену (одинаковый для всех).
- Узлы диаграмм парят; пакеты летят со шлейфом и покачиванием.
- Импакт (прилёт пакета, появление бейджа) → тряска камеры, пульс узла, кольца.
- Караоке-слова «выстреливают» пружиной в момент произнесения.
- Переход между сценами — один: slide снизу (в outro — fade) + вуш.

**Движок НЕ даёт — это на режиссёре, и за отсутствие этого критик бракует:**
- Движение по смыслу внутри кадра: элементы появляются / уходят / перестраиваются
  по ходу реплики, а не стоят готовым плакатом.
- Различие фаз одного визуала — композицией, а не только сменой подписей. Две-три
  сцены на одном визуале с одинаковой картинкой = брак.
- Хореография входов/выходов: стэггер групп, акцент на ударном слове, «жизнь»
  между фазами.

Следствия:
- Ставь `onWord` так, чтобы событие (прилёт, смена фазы, импакт) совпадало с
  ударным словом реплики.
- ≤3–4 импакта на сцену, иначе тряска = шум.
- Реплика сцены >12 сек — дели (это ~26 слов голосом Fenrir).

## Синхронизация
- Каждому пакету и бейджу state ставь `onWord` — элемент появляется в момент
  произнесения слова. Слово должно реально быть в реплике этой сцены (в форме
  показа, т.е. первой части разметки `{форма-показа|форма-озвучки}`).
- Порядок пакетов в массиве = порядок упоминания в реплике.
