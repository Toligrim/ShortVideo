# Каталог движения

Это параллель `catalog.md`: визуал выбирает объекты, motion выбирает изменение
их отношений. Главная метрика — понятный механизм в готовом ролике. Новый
примитив появляется только при доказанном пробеле; количество файлов не KPI.
Контракт и проверенный пример: `docs/motion-engine.md`,
`examples/motion-engine.json`, `video/src/scenes/UniqueInsertRaceVisual.tsx`.

## Декларация

У story — `beats[].motion`, у hook/diagram/code/terminal/outro — `scene.motion`.
Входящий стык задаётся `scene.transition` или `beats[].transition`. Поле `kind`
обязательно: `continuation | turn | contrast | finale`; `preset` можно опустить.
Камера и хореография не двигают караоке. Заголовок story остаётся над камерой.

```json
{
  "visual": "unique-insert-race",
  "onWord": "конфликт",
  "params": { "phase": "conflict", "key": "Космонавт", "index": "42" },
  "transition": { "kind": "contrast" },
  "motion": {
    "intent": "resolve",
    "camera": { "onWord": "конфликт", "target": { "x": 0.7, "y": 0.4 } },
    "entrance": "cascade",
    "cues": [
      { "id": "act", "onWord": "конфликт" },
      { "id": "resolve", "onWord": "копию" }
    ]
  }
}
```

`onWord` — точный токен формы показа, без учёта регистра, ударения и пунктуации.
Для второго «ключ» — `occurrence: 2`. Многословная форма `{UNIQUE INDEX|…}`
считается одним display-токеном и якорем `UNIQUE INDEX`. Подстроки здесь нельзя.
Не найденный якорь, повторный id cue и cue за границей бита — ошибка, не тихий
фолбэк. Старые `beat.onWord` сохраняют прежний нечёткий поиск для совместимости.
В episode запрещены ручные секунды, кадры, delay/duration/easing.

## Камера: `motion.intent` → preset

| Намерение | Preset | Когда использовать | Изменение при strength=1 |
|---|---|---|---|
| establish | hold | Дать прочитать общую структуру | Общий план scale .92, y −12 |
| focus | push-in | Выделить место операции | scale .92 → .99, внимание к target |
| reveal | pull-out | Открыть контекст вокруг детали | Текущий план → .89 |
| follow / compare | track | Перевести внимание к другой стороне | x до ±32 px; без target — −28 px; scale .95 |
| resolve | settle | Вернуть целый результат после действия | Возврат в общий план |

`camera.preset` может явно переопределять намерение. `target: {x,y}` —
нормализованная точка канваса, не идентификатор визуала; диапазон 0…1.
`strength` 0…1 регулирует амплитуду. Без `camera.onWord` движение начинается
с бита. Обычно занимает до 36 кадров, затем держит результат. См. точную
формулу в документации. Отсутствие jitter — нормально: пауза даёт прочитать.

## Переходы

| Смысл стыка | Preset | Когда использовать | Механика |
|---|---|---|---|
| continuation | match | Следующий шаг того же механизма | 28 px вверх + перекрытие прозрачностей |
| turn | push | Новая сторона/новая причина | 96 px влево, вход справа + прозрачность |
| contrast | wipe | Сравнение несовместимых исходов | Взаимодополняющая clipPath-шторка слева направо |
| finale | dissolve | Завершение доказательства | Прозрачность + 2% масштаб |

Сцены всегда перекрываются ровно на 10 кадров. Биты не меняют длину сцены:
предыдущая композиция выходит в первые ≤8 кадров нового бита. Только в этом
окне существуют два визуала. Полноэкранных цветных заливок/blur/3D нет.

## Хореография: API для автора визуала

`MotionStage` автоматически поставлен вокруг каждого бита. Новому визуалу
достаточно обернуть ≤4 смысловые группы в `MotionGroup`, указав стабильный
`id` и `index: 0…3`. `motion.entrance` выбирает словарь входов. Старые визуалы
получают камеру и выход/вход целой композиции без изменения своих файлов.

| Класс | Примитив | Когда использовать | Механика |
|---|---|---|---|
| Вход | cascade | Две стороны, причинная очередь | ±44 px; индексы задержаны на 0/4/8/12 кадров |
| Вход | rise | Возникновение из нижнего уровня | y +36 → 0 px |
| Вход | materialize | Новый объект/запись | scale .9 → 1 |
| Действие | transfer | Передать/сблизить/поставить в очередь | from → to по smoothstep |
| Действие | recoil | Отказ/отражение, объект сохраняется | from → to, дуга −20 sin(πp), opacity → .65 |
| Действие | pulse | Одно подтверждение на слове | scale 1 + .12 sin(πp), возврат к 1 |
| Действие | depart | Удалить/освободить/выйти | from → to + opacity 1 → 0 |

Вход заканчивается за ≤24 кадра вместе со стэггером; короткий бит сжимает
окно. Действие начинается по именованному cue, идёт ≤24 кадров и завершается
до следующего cue или конца бита. Параметры пространственные, не временные.
`useMotion().action(id)` даёт тот же p для SVG-линий, раскрытия строки и т.п.

Действие выбирается и в JSON: `motion.actors["request-b"] =
{"preset":"recoil","cue":"act","to":{"x":75,"y":-55}}`. Параметры from/to
ограничены ±540 px, overrides не более четырёх; cue должен быть объявлен в
motion.cues. У визуала стабильные id `index`, `request-a`, `request-b`,
`wait-lock` (только wait), `rejection` (только conflict); не назначай ход группе,
которой нет в данной фазе. Smoke проверяет отсутствующие объявленные группы.

У `unique-insert-race` поддержаны cues `act` (операция) и `resolve` (исход).
В старом JSON без cues они стоят на 30% и 70% бита; это страховка для старого
материала, не допустимая замена режиссуре нового. Фазы: request — раздельный
вход запросов, принятие/отказ; check — два чтения к индексу; insert — схождение
с исчезновением запросов и заполнением строки; wait — парковка B и освобождение
замка; conflict — отбрасывание B при сохранённом A. Пример переиспользует
настоящую озвучку `auto-20260910-052001`, не заказывает TTS.

## Gap-скан движения (обязателен для нового эпизода)

Рядом с таблицей визуалов в `episodes/<slug>.gap-scan.md` добавь таблицу:
`идея → бит/стык/фаза → отношение ДО/ПОСЛЕ → нужный ход → ближайший примитив → 1–5 → cue/объект → решение`.
Внутри одной идеи перечисли нужные камера/стык/объекты, но для порога считай
ИДЕИ, а не строки и не глаголы. 5 — буквально выражает изменение отношений;
4 — выражает параметризацией/композицией; 3 — движение есть, смысл читается
лишь по подписи; 2 — декоративное; 1 — нужного действия нет. Оценка идеи —
минимум её существенных ходов. Проверка существующих движений столь же
обязательна, как проверка визуалов.

**Порог motion-кузницы:** ≤3 у ≥3 смысловых идей → выковать хотя бы один
переиспользуемый примитив; ≤3 у 1–2 идей → один примитив или письменное
обоснование композиции; всё ≥4 → новых примитивов 0 — норма. Новый camera
preset не закрывает пробел «объект должен исчезнуть/передать значение».

## Дисциплина кузницы

1. Назови изменение отношений и минимум два разных сюжета для повторного
   применения. Если имя содержит slug или тему ролика — это не примитив.
2. Спека: входные пространственные параметры, cue, состояние до/в/после,
   диапазоны, 3 контрольных кадра, стоимость и ограничение короткого бита.
3. Реализуй небольшую чистую функцию в `src/lib/motion/` (ориентир ≤80 строк
   на один ход). Расширь соответствующий registry в `camera.ts`,
   `transitions.tsx` или `choreography.ts`. Сложный ход вынеси в отдельный файл.
   Только frame/якоря, никаких эффектов по wall-clock, CSS animations, Date,
   Math.random, сетевых ресурсов. Декларации — `types.ts` + JSON Schema.
4. Композиция нескольких ходов предпочтительнее нового. Не делай новый
   примитив ради силы, стороны или другого текста — это параметры.
5. Тест: начало/середина/конец, короткий бит, повторный seek. Затем tsc,
   3 still из одного bundle и повтор первого кадра в конце. Новый дорогой
   эффект сравни с прежним на одинаковых кадрах. Не добавляй зависимости.
6. Применение в эпизоде + запись каталога + тест в одном коммите. В отчёте:
   новые имена, что теперь можно выразить, где ещё применить, кадры и стоимость.

Формат новой записи: `id / класс / намерение / когда использовать / когда не
использовать / параметры и диапазоны / якоря / формула и предел кадров /
стоимость DOM / короткий бит / путь к коду / пример / подтверждение`. Таблицы
выше — стартовый словарь; при добавлении нового хода эти поля обязательны.
