# Каталог сцен (v1)

Эпизод = 4–7 сцен, начинается с `story` (или простого `hook`) и заканчивается `outro`.
Реплика сцены — 1–3 предложения, ~7–12 секунд речи.

## hook — открывающий кадр
Крупный заголовок, слова влетают по одному; субтитров нет (заголовок и есть текст).
Хук должен создавать интригу или обещание за первые 2 секунды.

| Поле | Что писать |
|---|---|
| `title` | ≤6 слов, цепляющий («3 пакета, без которых нет интернета») |
| `subtitle` | необязателен; тема + время («TCP handshake за 50 секунд») |

## story — сториборд: каждая фраза обыграна своим битом
Лучший опенер. Сцена = последовательность битов; бит стартует на слове-якоре
`onWord`, между битами камера прыгает (зум/сдвиг). Каждое слово диктора получает
свою картинку — максимум движения.

Когда использовать `password-leak`: любой сюжет про пароль/секрет, уходящий по сети
в открытом виде — перехват, незашифрованный логин, демонстрация уязвимости.

Когда использовать `hash-table`: буквальное объяснение хеш-функции, индекса массива и быстрого поиска по ключу.

Когда использовать `collision-compare`: сравнение chaining и open addressing на одной и той же коллизии; не заменяет общий `diagram`, если нужны произвольные узлы и пакеты.

Когда использовать `heap-graph`: буквальное объяснение достижимости от корней, цепочек ссылок и отсоединённых циклов; `mode: roots` — для старта обхода, `mode: unreachable` — для мусора.

Когда использовать `gc-sweep`: буквальное объяснение фаз mark-and-sweep или поколений кучи; `mode: generations` — когда речь о частой уборке молодой части и редком сканировании старой.

Когда использовать `medal-mint`: сюжет буквально про медаль/монету/печать с девизом, которая
чеканит или проявляет два символа (в бинарной истории — 1 и 0); не для абстрактных «двух
состояний» без физического предмета-медали.

Когда использовать `ancient-code`: показать, что задолго до текущего героя кто-то уже
записывал двоичную идею в другой форме — гексаграммы, слоги стиха, любой историко-культурный
код, который переводится в 0/1; `mode: hexagram` — линии/триграммы, `mode: syllable` — метрика
стиха или другая последовательность длинный/короткий.

Когда использовать `verdict-scan`: любой сюжет про автоматическую проверку кода/поведения,
где честного ответа не существует — антивирус, линтер, статический анализатор; вопрос
остаётся открытым (мигающий вердикт, а не готовый ответ).

Когда использовать `paradox-box`: диагонализация/самоприменение — программа или функция
берёт саму себя как вход и опровергает предсказание о себе (проблема остановки, теорема
Райса, парадокс лжеца в коде); `stage: setup` — для момента самоприменения и развилки,
`stage: crack` — для момента, когда контрпример разрушает предполагаемый оракул/детектор.

Когда использовать `proof-sequence`: рекуррентная последовательность, итерации которой
доказывают свойство числа — тест Люка—Лемера для простых Мерсенна, любые итеративные
проверки «стартуй, крути шаги, смотри на последний член»; `mode: run` — для бытовой
интуиции (конвейер превращений от старта к нулю), `mode: steps` — для инженерной формулы
с явным рядом шагов и стрелкой на итоговый нуль.

Когда использовать `fft-wave`: гигантские умножения, для которых не хватает обычных
алгоритмов, и их ускорение быстрым преобразованием Фурье — разложение сигнала/числа на
частоты; `phase: square` — для «миллиардов знаков и обычное умножение не справится»,
`phase: fft` — для момента разложения волны на синусоиды и импульса ускорения.

Когда использовать `qr-repair`: любой сюжет про QR/штрих-код и его живучесть — царапины,
оторванный угол, стёртая часть рисунка, избыточность и восстановление по уцелевшим.
`phase: damage` — момент повреждения (стирание, поцарапали, "не прочтётся"); `phase: restore` —
момент, когда код восстанавливается и успешно читается (бейдж «КОД ЧИТАЕТСЯ»);
`phase: encode` — резка данных на кодовые слова по 8 бит и добавление контрольных
(кодовые слова Рида—Соломона); `phase: levels` — уровни коррекции L/M/Q/H и рост размера
квадрата вместе с защитой. `damaged: 0..1` — доля стёртых модулей; `weather: true` — дождь
и блики поверх матрицы (условия платформенных дверей метро).

Когда использовать `hll-estimate`: HyperLogLog — подсчёт уникальных без хранения.
`phase: hash` — момент «каждый ай-ди → 64 бита», подсвети хвост ведущих нулей (буквально лента 64 бит с выделенными первыми нулями и подписью 14 бит индекс / 50 бит ранг); `phase: registers` — момент «поток на 16384 регистров по 6 бит» (сетка 128×128 =12288 байт, в каждом максимум нулей, 6 бит хватает до 50); `phase: harmonic` — момент гармонического среднего и формулы ошибки 1.04/√m (m=16384→0.81%) с потолком 2⁶⁴; `phase: scale` — финал «память фиксирована 12 КБ, <1%, PFMERGE сливает два HLL».

Когда использовать `bloom-bitarray`: буквальное объяснение механизма фильтра Блума — ключ проходит через k хеш-функций, каждая ставит единицу в свой слот битового массива; не хранит сами значения, только «был/не был». Используй для момента «несколько хешей ставят единицы».

Когда использовать `bloom-probe`: момент проверки запроса к фильтру Блума — ключ сканирует проверяемые биты, все единицы = «возможно есть» (ложное совпадение), хотя бы один ноль = «точно нет» и файл пропускается. `result: no` — для сцен про экономию чтений диска (RocksDB), `result: maybe` — для односторонней ошибки ( «есть» не гарантирует присутствие).

Когда использовать `union-find`: буквальное объяснение disjoint-set (системы непересекающихся множеств) — parent pointers как дерево, подъём `find` от узла к корню по указателям, сжатие путей (перепись указателей прямо на корень) и union by rank (меньшее дерево — под бо́льшим). `phase: find` — для «ищем корень / поднимаемся по ссылкам», `phase: compress` — для «дерево уплощается, почти константа», `phase: union` — для «склеиваем два множества».

Когда использовать `shuffle-deck`: сюжет о равномерной случайной перестановке и Fisher–Yates. `phase: naive` — независимые обмены с любым индексом и неизбежный перекос; `phase: fair` — диапазон выбора уменьшается после фиксации позиции; `phase: count` — произведение N × (N−1) × … показывает ровно N! равных путей.

Когда использовать `coin-pair`: буквальное показание двух бросков монеты попарно — совпадение/различие, отбор пар для метода фон Неймана. `match: true` — для момента «одинаковые, отбрасываем», `match: false` — для момента «разные, есть информация».

Когда использовать `bit-extractor`: таблица соответствий фон Неймана — какие пары дают бит, какие отбрасываются; наглядная сводка правила HT=1, TH=0, HH=TT → пропуск.

Когда использовать `rule-110`: буквальное объяснение правила клеточного автомата — 8 комбинаций трёх соседей дают 0 или 1; `mode: truth-table` — полная таблица из 8 строк, `mode: cell-eval` — оценка одной конкретной клетки на ленте.

Когда использовать `glider-collision`: движение локализованных структур (глайдеров) по ленте клеточного автомата, их столкновение и порождение новых паттернов — ключевая механика, из которой следует универсальность.

Когда использовать `debruijn-cycle`: любой сюжет про последовательность де Брёйна — циклическая строка, где каждое окно фиксированной длины уникально. `phase: window` — момент «кольцо длины 2ⁿ и скользящее окно n бит»; `phase: graph` — момент построения эйлеровым обходом графа де Брёйна (вершины n−1 бит, рёбра n бит); `phase: angle` — момент абсолютного датчика угла (одна дорожка, чтение n точек → однозначный угол среди 2ⁿ); `phase: linear` — момент «разрежь кольцо и допиши n−1 бит» (линейная длина 2ⁿ+n−1).

Когда использовать `hamming-word`: буквально показать устройство кода Хэмминга (7,4), разницу между четырьмя данными и тремя проверочными позициями, а также одиночный перевёрнутый бит.

Когда использовать `hamming-syndrome`: показать, как три проверки чётности превращаются в двоичный синдром — адрес повреждённой позиции; `mode: groups` — для состава групп, `mode: syndrome` — для финального нахождения ошибки.

## `counter`

Когда использовать: любой сюжет про счётчик Морриса и вероятностный подсчёт «в обмен на память». `phase: exact` — момент «точный счётчик: каждое событие плюс один, память растёт без предела» (гигантское число, растущая стопка 8-байтовых ячеек, красный бейдж); `phase: flip` — момент «прибавляю единицу только иногда»: детерминированный поток событий, монетка, редкие +1, байтовый регистр уровня и ожидаемое ≈2^X; `phase: decay` — момент «чем выше число, тем реже шаг»: лестница X=1..8 с шириной полос по шансу 2^-X и ползущим вверх highlight; `phase: formula` — момент «вероятность шага — два в степени минус уровень»: карточка P(+) = 2⁻ˣ с подстановкой текущего X и тремя примерами; `phase: logarithm` — момент «хранится логарифм, а не количество»: регистр X = 17 ↔ ≈131 071 (2¹⁷ − 1), после импакта бейдж «8 бит ловят до 130 000 событий»; `phase: accuracy` — момент «ошибка не больше 24%»: шкала 0–50% с маркером на 24% и сетка 100 точек (95 зелёных, 5 красных); `phase: tradeoff` — момент «точность меняется на память»: две карточки (точный vs Моррис) и бейдж обмена.
