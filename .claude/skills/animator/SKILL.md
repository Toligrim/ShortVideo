Ты — аниматор конвейера ShortVideo. Ролик описывается ТОЛЬКО декларативным JSON
(эпизод из сцен) — ты не пишешь видео-код, ты пишешь партитуру, движок Remotion
рендерит её детерминированно.

## Что прочитать перед работой

1. `catalog.md` (рядом с этим файлом) — типы сцен, их параметры, когда какую использовать.
2. `style.md` — правила текста, композиции и озвучки. Нарушать нельзя.
3. `examples/` — эталонные эпизоды. Новый эпизод должен выглядеть так же по духу.
4. `schema/scenes.schema.json` (корень проекта) — формальные ограничения полей.

## Пайплайн производства эпизода

```bash
# 1. Написать эпизод
episodes/<slug>.json                     # slug: kebab-case, латиница

# 2. Валидация схемой (обязательно до озвучки)
python3 tools/validate.py episodes/<slug>.json

# 3. Озвучка + тайминги слов (только Gemini TTS; нет квоты/сети → падает,
#    без фолбэка на другой TTS)
venv/bin/python tools/tts_scenes.py \
  episodes/<slug>.json --out video/public/episodes/<slug>
cp episodes/<slug>.json video/public/episodes/<slug>/script.json

# 4. Контрольные кадры (быстро, до полного рендера)
cd video && npx remotion still Episode /tmp/check.png --frame=<N> \
  --props='{"episodeId":"<slug>"}'
# посмотри 2–3 кадра из разных сцен инструментом Read: текст читаем? ничего не перекрывается?

# 5. Полный рендер (долгий — в фоне)
cd video && npx remotion render Episode out/<slug>.mp4 --props='{"episodeId":"<slug>"}'

# 6. Отправка в Telegram — ОБЯЗАТЕЛЬНЫЙ финальный шаг, не опция
cd .. && python3 tools/telegram_bot.py send-video video/out/<slug>.mp4 --caption "<тема>"
```

Токен и chat_id бота лежат в `.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_CHAT_ID`) —
скрипт подхватывает их сам, ничего передавать вручную не нужно. Любой готовый
рендер эпизода должен закончиться отправкой в бот.

## Ключевые факты о движке

- Длительность сцены = длительность её реплики + 0.75 сек паузы. Тайминги НЕ пишутся
  в JSON — они вычисляются из аудио автоматически.
- Разметка реплики `{форма-показа|форма-озвучки}`: на экране и в субтитрах — первая
  часть, голос произносит вторую. Обе части — РЕАЛЬНЫЙ текст, который ты сам
  подставляешь, не служебные слова: `{TCP|ти си пи}`, `{биткоин|биткоин}`.
  ⚠️ Буквальные строки «SHOW» и «скажи» в примерах ниже — только имена мест
  для подстановки (как `<TERM>`), НИКОГДА не пиши их в разметку дословно —
  `{SHOW|термин}` попадёт на экран как есть и сломает субтитры (прецедент
  auto-20260831-050001, 31.08.2026; `tools/validate.py` теперь фейлит такое
  жёстко). Разметка обязательна для всех терминов/аббревиатур.
  Правила транслитерации — в `~/.claude/commands/tts.md` (словарь) и style.md.
- Якорь `onWord` (пакеты, бейдж state) синхронизирует появление элемента с моментом
  произнесения слова. Значение — слово из реплики этой же сцены (форма-озвучки).
- Караоке-субтитры рендерятся автоматически на всех сценах, кроме hook.
- Иконки узлов — любые из lucide (kebab-case): smartphone, server, globe, skull,
  lock, key, shield, database, wifi, file-text, user, bug, cloud...

## Кузница: быстрая проверка сцены без озвучки

Композиция `Preview` рендерит ОДНУ сцену с синтетическими таймингами слов —
кадр готов за секунды, TTS не нужен:

```bash
cd video && npx remotion still Preview /tmp/preview.png --frame=<N> \
  --props='{"scene": {<полный JSON сцены с narration>}}'
```

Используй для: проверки нового визуала, отладки композиции кадра, подбора
параметров. Смотри результат инструментом Read. Итерация дешёвая — не бойся
пробовать варианты.

## Если нужной сцены нет в каталоге

Не выкручивайся через неподходящую сцену. Расширь язык:
1. Добавь React-компонент в `video/src/scenes/` по образцу существующих
   (пропсы: scene, words, frames; примитивы — из `video/src/primitives/`).
2. Зарегистрируй тип в `video/src/lib/types.ts`, `video/src/Root.tsx` (SceneRenderer)
   и в `schema/scenes.schema.json`.
3. Опиши сцену в `catalog.md` (параметры + когда использовать) — язык растёт, документация обязана расти вместе с ним.
4. Проверь контрольным кадром, что сцена выглядит по правилам style.md.
