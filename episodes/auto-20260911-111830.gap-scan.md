## 2. Новый visual

Новых визуалов N = 1: `bfcache-restore` в `video/src/scenes/BfcacheRestoreVisual.tsx`.

Фазы (6): `visit`, `snapshot`, `freeze`, `book`, `restore`, `ordinary-load`. Они разделены изменением композиции и отношений объектов: цельный браузер с сохранёнными scroll/field; браузер слева и memory-card справа; уходящий live-document и замороженный snapshot с `JS · PAUSED`; отдельная раскрытая книга на столе; snapshot слева и восстановленный браузер справа с теми же scroll/field и `JS · RUN`; блокеры слева и `GET /document` с пустым строящимся экраном справа.

Visual не является мега-компонентом: это один узкий механизм, шесть фаз, до трёх MotionGroup с объектами в каждой фазе, не более четырёх смысловых групп и одна нижняя badge-плашка. Текст narration на канвас не выносится; короткие подписи обозначают только объекты и состояния. Параметр `phase` переиспользует код без превращения пяти сцен в одно изображение.

Документация зарегистрирована в `.claude/skills/animator/catalog.md`; тип добавлен в `video/src/lib/types.ts`, enum — в `schema/scenes.schema.json`, маршрутизация и cue/SFX — в `video/src/scenes/StoryScene.tsx`.

## 4. Независимый motion gap-скан

Скан выполнен по тем же пяти идеям, независимо от visual gap-скана. «До/после» означает отношение объектов, а не движение камеры.

| ID | Бит / фаза | Объекты ДО → ПОСЛЕ | Нужный осмысленный ход | Ближайший примитив | Оценка | Cue / объект | Решение |
|---|---|---|---|---|---:|---|---|
| M1 | сцена 0, visit | browser с scroll/field → тот же browser становится возвращённым состоянием рядом с history | history возвращается, field подтверждает сохранённость | `transfer` + `pulse` в `MotionGroup` | 4/5 | `back` / `history`; `state` / `field`; `restore` / экран | Использован существующий registry: transfer показывает возврат, pulse — сохранённое поле. |
| M2 | сцена 1, snapshot | live browser слева → memory-card справа, JS heap появляется внутри снимка | документ переносится в память, состав снимка подсвечивается по частям | `transfer` + `pulse` | 4/5 | `save` / `document`; `snapshot` / `snapshot`; `heap` / `heap` | Использован `MotionGroup`; отдельный heap предотвращает слияние с HTTP-ответом и дублирование объекта. |
| M3 | сцена 2, freeze → book | live document + execution → frozen snapshot + paused JS; затем snapshot-логика → раскрытая книга на столе | уход документа и фиксация состояния, затем возврат книги на стол | `depart` + `pulse` + `transfer` | 4/5 | `freeze` / `document` и `snapshot`; `pause` / `execution`; `book` / `book`; `table` / `return` | Нового примитива не требуется: смысл выражают смена отношений и существующие depart/pulse/transfer. |
| M4 | сцена 3, restore | snapshot слева → browser справа с теми же scroll/field и JS running | snapshot достаётся, документ входит в экран, выполнение возобновляется | `depart` + `transfer` + `pulse` | 5/5 | `restore` / `snapshot` + `document`; `resume` / `return`; `continue` / document | Существующие примитивы точно покрывают передачу и возобновление; camera только направляет взгляд и не засчитывается как движение. |
| M5 | сцена 3, ordinary-load | blockers + отсутствие snapshot → GET /document и пустой browser | запрет разрывает путь snapshot, запрос приводит к пересборке | `pulse` + `transfer` | 4/5 | `rebuild` / `blockers` + `request`; `again` / `page` | Использованы pulse/transfer; dashed arrow — визуальная связь «нет snapshot», не новый motion-примитив. |

Все motion-идеи ≥4, поэтому новых motion-примитивов M = 0. Не создавался примитив ради другого текста или силы: существующие `MotionGroup` presets `transfer`, `depart` и `pulse` меняют отношения объектов и синхронизируются с именованными cues. Seek-проверка и отдельная стоимость нового motion-примитива не требуются для M=0. Стоимость motion-изменения: 0 новых registry-примитивов, только уже зарегистрированные transform/opacity-переходы; стоимость нового visual — один параметрический компонент и его phase-ветвление.

Переходы: `continuation/match` удерживает один механизм между соседними объяснениями, `turn/push` открывает snapshot, `contrast/wipe` отделяет полный состав и fallback-загрузку, `finale/dissolve` собирает вывод. Внутри каждой фазы cue-порядок совпадает с речью: `save → snapshot → heap`, `freeze → pause`, `restore → resume → continue`, `rebuild → again`.
