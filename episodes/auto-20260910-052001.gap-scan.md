# Gap-скан и раскадровка: auto-20260910-052001

Вход: утверждённый `episodes/drafts/auto-20260910-052001.draft.json`.
Все пять реплик в episode JSON перенесены дословно, включая разметку
`{UNIQUE INDEX|уника́льный и́ндекс}` и `{ATOMIC INSERT|атома́рной вставки}`.
Новая визуальная причинная цепочка нужна потому, что предварительный `SELECT`
может совпасть, а гарантию даёт именно ограничение уникальности, реализованное
уникальным индексом при конкурентной вставке.

## Обязательная раскадровка

### Блок 1

- Сущности → объекты: два человека/два запроса, сервис, ник «Космонавт», два экрана регистрации, две заявки. В кадре — две карточки `ЗАПРОС A/B` с одним ником и статусом `СВОБОДНО`; после импакта A остаётся принятым, B тускнеет и получает отказ.
- Действия → движения: почти одновременный ввод показывается параллельными карточками; итог приходит ударом на заявке A, затем второй экран визуально теряет статус. Второй beat — короткий `title-slam` для детективного вопроса, без повторения реплики на canvas.
- Ударные слова → onWord: первый beat стартует на `Ты`; финальный удар — `исчез` → `title-slam`.

### Блок 2

- Сущности → объекты: два запроса, внутренняя база, пустая строка индекса, имя. `unique-insert-race/check` показывает две стрелки к одной пустой строке; `hash-table` даёт дополнительный крупный план маршрута имени в пустой слот.
- Действия → движения: запросы входят одновременно и сходятся к пустой строке; затем ключ проходит `h(ник)` к пустой ячейке. Это один причинный шаг «оба прочитали пусто», а не набор отдельных кликов.
- Ударные слова → onWord: первый beat — старт сцены без отдельного якоря; крупный план пустого слота начинается на `записи`.

### Блок 3

- Сущности → объекты: поле никнейма, `UNIQUE INDEX`, строка с номером `42`, значение «Космонавт», кассовая книга. `unique-insert-race/insert` ставит две стрелки в одну строку; `hash-table` поддерживает аналогию «ключ → номер места».
- Действия → движения: две вставки физически сходятся к одной индексной строке; второй beat переводит тот же ключ в пронумерованный слот, не добавляя новую микросцену.
- Ударные слова → onWord: первый beat — старт сцены; крупный план номера строки начинается на `номер`.

### Блок 4

- Сущности → объекты: запрос A, запрос B, конкурентные транзакции, строка уникального индекса, фиксация, конфликт. `wait` оставляет A у строки с замком, а B — в очереди ожидания; `conflict` раскладывает зелёный `A · COMMIT` и красный `B · UNIQUE VIOLATION`.
- Действия → движения: первый запрос фиксируется, второй останавливается у занятой строки; после завершения первой вставки красный путь B получает отказ и не проходит в новую запись.
- Ударные слова → onWord: `закрепляет` → фаза `wait`; `конфликт` → фаза `conflict`.

### Блок 5

- Сущности → объекты: ограничение базы, `UNIQUE INDEX`, две проверки, две вставки, один победитель, конфликт и мостик к следующему сюжету. Финал — стандартный `outro` с четырьмя короткими объектными bullet-ярлыками и CTA.
- Действия → движения: повторная проверка причинной цепочки в караоке; outro визуально собирает итог, а не добавляет новую схему. Отдельных `onWord` у `outro` схема не предусматривает.
- Ударные слова → onWord: для outro-якорей нет структурного поля; ударные слова `UNIQUE INDEX`, `атомарно`, `конфликт`, `Подпишись` остаются единственным дословным текстом в караоке.

## Сгруппированные смысловые идеи и gap-скан

Повествование сгруппировано в пять идей — по одной на каждый блок, без дробления
на отдельные клики, стрелки или движения.

| Идея из реплик | Лучший существующий visual | Оценка 1–5 | Решение | Оценка после |
|---|---|---:|---|---:|
| Две почти одновременные регистрации борются за один знакомый ник | `collision-compare` | 2 | Очередь кузницы: `unique-insert-race/request` показывает два экрана и разные исходы | 5 |
| Два запроса одновременно проверяют ещё пустое имя и оба идут дальше | `hash-table` | 2 | Очередь кузницы: `unique-insert-race/check`; `hash-table` оставлен только как крупный план пустого слота | 5 |
| Уникальное ограничение представлено одной пронумерованной строкой индекса | `hash-table` | 3 | Очередь кузницы: `unique-insert-race/insert` с явным `UNIQUE INDEX` и сходящимися вставками | 5 |
| Конкурентная вставка ждёт первую транзакцию и выдаёт конфликт проигравшему | `collision-compare` | 2 | Очередь кузницы: `unique-insert-race/wait` → `conflict` | 5 |
| Гарантию даёт ограничение уникальности, а не одиночная предварительная проверка | `collision-compare` | 3 | Очередь кузницы: финальная фаза `conflict` с одним `COMMIT` и одной `UNIQUE VIOLATION`; outro формулирует правило | 5 |

До кузницы: **5 идей**, из них **5 оценок ≤3**. Все пять покрыты одним
небольшим параметрическим visual, а не отдельными одноразовыми компонентами.
`hash-table` и `collision-compare` проверены и не выдают полный причинный шаг:
первый показывает адресацию одного ключа, второй — chaining/open addressing,
но ни один не показывает ожидание конкурентной транзакции и конфликт
уникального ограничения.

## Очередь кузницы и новый visual

Создан `unique-insert-race` на **5 фаз** (меньше шести), с параметрами `key` и
`index`:

1. `request` — две формы регистрации с одним ником; после импакта один статус принят, второй отклонён.
2. `check` — два запроса читают одну пустую строку индекса.
3. `insert` — две стрелки доходят до одной строки `UNIQUE INDEX`.
4. `wait` — первая транзакция фиксирует строку, вторая ждёт у замка.
5. `conflict` — победитель остаётся, проигравший получает `UNIQUE VIOLATION`.

В каждой фазе не более четырёх смысловых визуальных объектов и одной короткой
подписи помимо заголовка фазы; строки narration на canvas не выносятся. При
переиспользовании в эпизоде соседние кадры используют разные фазы и разные
композиции: `request → check → insert → wait → conflict`.

Документация visual: `.claude/skills/animator/catalog.md`.
Реализация visual: `video/src/scenes/UniqueInsertRaceVisual.tsx`.

## Состав сцен

`story(request + title-slam) → story(check + hash-table) →
story(insert + hash-table) → story(wait + conflict) → outro`.

В story-сценах нет повторяющихся соседних картинок: переходы между блоками
заканчиваются/начинаются разными visual или фазами.

## onWord-якоря

- Сцена 1: `Ты` → `unique-insert-race/request`; `исчез` → `title-slam`.
- Сцена 2: `записи` → `hash-table`; первый `check` стартует с начала сцены.
- Сцена 3: `номер` → `hash-table`; первый `insert` стартует с начала сцены.
- Сцена 4: `закрепляет` → `unique-insert-race/wait`; `конфликт` → `unique-insert-race/conflict`.
- Сцена 5: `outro` не имеет beats/state/packets; все ударные слова остаются в дословной караоке-реплике.
