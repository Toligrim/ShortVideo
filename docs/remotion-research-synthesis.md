# Синтез: два deep research отчёта по экосистеме Remotion (06.08.2026)

Два независимых deep research прогона по одному промпту (список 207 Remotion-репозиториев
+ описание архитектуры ShortVideo, см. `~/projects/GitHub_Research/findings/`). Сырые отчёты:
[remotion-research-1-claude.md](remotion-research-1-claude.md) (глубокий разбор QA-контура),
[remotion-research-2-gemini.md](remotion-research-2-gemini.md) (учёл железо — Pi 5 ARM64).

## Согласны оба

- **Не трогать генеративку и голос.** AI-видео/картинки (Veo/Kling/FLUX), voice cloning,
  платные TTS, GUI-редакторы с таймлайном — вне рамок. Причина у обоих одна: ломает
  детерминированность и word-boundary тайминги, на которых держится вся система `onWord`.
- **Каталог визуалов — точка роста №1.** Оба называют `video-shotcraft`
  (recipe card: назначение / энергия / длительность / грабли) источником формата.
  Закрывает найденный ранее drift: 11 визуалов в коде против 8 задокументированных в `catalog.md`.
- **CodeHike для code-сцен — да, но дорого и в конце.** `remotion-dev/template-code-hike`
  даёт токен-морфинг при изменении кода (вместо перекраски Prism целиком) — оба ставят это
  последним пунктом по цене.

## Уникально для отчёта 1 (архитектура QA)

Вгрызается в критика — то, что второй отчёт не тронул вообще:
- Критик сейчас смотрит кадры на фиксированных 35%/75% сцены — может попасть в момент,
  когда пакет ещё летит. Предложение: выбирать кадры по `onWord`-событиям
  (settled/motion/final), паттерн из `Zane-0x5a/remotion-director`.
- Вердикт критика привязать **хешем** к версии JSON + word boundaries
  (`paper-collage-video`) — TTS может сдвинуть слово без изменения текста, и старый
  одобренный кадр останется формально валиден для уже другой версии.
- Отдельный «tempo-аудит»: не читаемость кадра, а сколько кадров держится состояние.
- Явно расписано, что НЕ брать: multi-draft генерацию (`remotion-director`), бесконечный
  critic loop, matrix-рендер в GitHub Actions (называет преждевременным).

## Уникально для отчёта 2 (железо Pi 5)

Единственный, кто учёл, что рендер идёт на Raspberry Pi 5 (16 ГБ, ARM64) — конкретные,
сразу проверяемые флаги:
- `--concurrency=1` (максимум 2) — иначе OOM-killer на параллельных Chromium
- `--browser-executable=chrome-headless-shell` — новый Chromium снёс старый headless-режим
- `--codec=h264 --audio-codec=aac` — сборки FFmpeg под ARM64 обычно без AV1-энкодера
- `--gl=swiftshader` — против утечек GPU-контекста на long-form рендерах

Плюс два конкретных находки:
- `stefanwittwer/remotion-animated` — декларативная обёртка `<Animated>` вместо ручных
  `interpolate()/spring()` в каждом визуале — меньше шаблонного кода в кузнице.
- `lhr0909/asciinema-mp4` — реальные `.cast`-записи терминальных сессий вместо
  посимвольной печати в `TerminalScene`.
